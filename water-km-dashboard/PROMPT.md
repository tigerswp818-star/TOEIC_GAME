# คู่มือการเขียน Prompt สร้าง KM Dashboard ด้วย AI

เอกสารนี้คือ "สูตร" ที่ทีมใช้สั่งงาน AI (Claude / ChatGPT) ให้สร้าง Dashboard ชิ้นนี้
เก็บไว้เพื่อ (1) นำเสนอผู้บริหารว่าเราใช้ AI อย่างไร (2) ให้รุ่นน้องใช้ต่อยอดเพิ่มเนื้อหาได้เอง

---

## 1. หลักคิด: Prompt ที่ดีมี 5 ส่วน

| ส่วน | ทำหน้าที่ | ตัวอย่างจากงานนี้ |
|------|-----------|-------------------|
| **บทบาท (Role)** | บอก AI ว่าให้สวมบทอะไร | "คุณเป็นนักพัฒนาเว็บ + นักออกแบบ Dashboard" |
| **บริบท (Context)** | เล่าที่มาและผู้ใช้งาน | "สรุปบทเรียนระบบสูบส่ง-สูบจ่ายน้ำ ใช้สอนพนักงานใหม่และนำเสนอผู้บริหาร" |
| **ข้อมูลดิบ (Data)** | แนบความรู้ที่จะให้แสดง | เนื้อหาจากสไลด์/สมุดจดทั้งหมด (สำคัญที่สุด!) |
| **สเปกงาน (Spec)** | ระบุหน้าตา ฟีเจอร์ เทคโนโลยี | "HTML ไฟล์เดียว เปิดได้เลย มีกราฟ PTC มีฟอร์มรับ-ส่งเวร" |
| **เงื่อนไข (Constraints)** | กรอบที่ห้ามหลุด | "ภาษาไทย, แยกไฟล์ข้อมูลออกจากโค้ดเพื่อ Add-on ได้, ระบุแหล่งที่มาของตัวเลข" |

> เคล็ดลับ: **AI ไม่รู้ข้อมูลหน้างานของเรา** — ถ้าไม่แนบข้อมูลดิบ (ชื่อสถานี, Flow, Pressure)
> AI จะ "มโน" ตัวเลขขึ้นมาเอง ซึ่งอันตรายมากสำหรับงานประปา
> ดังนั้นให้จดข้อมูลจริงก่อน แล้วค่อยป้อนให้ AI จัดรูปแบบ

## 2. Master Prompt ที่ใช้สร้าง Dashboard นี้ (คัดลอกไปใช้ต่อได้)

```
คุณเป็นนักพัฒนาเว็บและนักออกแบบ Dashboard มืออาชีพ

# บริบท
ผมเป็นพนักงานใหม่ของหน่วยงานประปา หัวหน้าให้สรุปบทเรียนเรื่อง
"ระบบสูบส่งและสูบจ่ายน้ำ" เป็น Dashboard องค์ความรู้ (KM) ใช้:
- สอนพนักงานใหม่รุ่นถัดไป
- นำเสนอผู้บริหารวันศุกร์นี้
- เป็นสมุดพกข้อมูลตอนย้ายไปประจำสถานี

# ข้อมูลดิบ (จากเอกสาร/สมุดจด — ใช้เฉพาะข้อมูลนี้ ห้ามแต่งตัวเลขเพิ่ม)
[วางเนื้อหาสรุปทั้งหมดตรงนี้ เช่น:
- โรงงานผลิต 4 แห่ง: บางเขน >4 ล้าน ลบ.ม./วัน, มหาสวัสดิ์ >1 ล้าน, สามเสน ~2 แสน, ธนบุรี ~5,000 ลบ.ม./ชม.
- โครงสร้าง 5 ชั้น: โรงงานผลิต → อุโมงค์ Ø3,200 มม. → สถานีสูบจ่าย → ท่อประธาน Ø400+ มม. → DMA ~1,000 มาตร
- สถานี: ปั๊มขนาน 4+1, ปรับรอบ 500–720 RPM, แรงดันเข้า ~15 ม. → ออก ~20 ม.
- RTU >200 จุด: P = วัดแรงดัน, UZ = วัด Flow+Pressure, เลขท้าย = โซนสาขา
- PTC Curve: peak เช้า 05–09 น., margin ±0.5 ม., สาขาขอ micro-adjust ได้
- 3 หน่วยงาน: กคจ. (สมอง) / สถานี (กล้ามเนื้อ) / สาขา (พื้นที่)
- ฉุกเฉิน: ผันน้ำผ่านวาล์ว RCV, วิกฤตผลิตหาย 2 ล้านคิว → หรี่แรงดัน/ผันน้ำ/กักสำรอง
- DMA: แรงดัน 20 ม. → 4.4 ม. → 2.0 ม., Step-Test ตี 3 หาท่อรั่ว
- สายส่ง 4 line (MH มหาสวัสดิ์, TR1 บางเขน, TR2 บางเขน, TR3 บางเขน) จ่ายเข้าสถานีสูบจ่าย 10 แห่ง]

# สเปกงาน
1. เว็บ HTML/CSS/JS ล้วน ไม่ใช้ไลบรารีภายนอก เปิดไฟล์ index.html ได้ทันที
2. ภาษาไทยทั้งหมด โทนสะอาด อ่านง่าย เหมาะฉายจอนำเสนอ
3. มีส่วน: ภาพรวม+แผนภาพเส้นทางน้ำ(คลิกดูรายละเอียดได้), โครงสร้าง 5 ชั้น,
   เทียบสูบส่ง/สูบจ่าย, กายวิภาคสถานี(มีเกจ+สไลเดอร์ RPM),
   RTU&SCADA, กราฟ PTC 24 ชม.(มี tooltip), 3 หน่วยงาน,
   ภาวะฉุกเฉิน(มีปุ่มจำลองผันน้ำ), DMA+Step-Test จำลอง,
   ตารางข้อมูลจริง TR 3 + สจ. 10 แห่ง (แก้ไขได้ เก็บ localStorage, export JSON),
   ฟอร์มบันทึกรับ-ส่งเวร (เก็บ localStorage, export CSV), คลังความรู้ Add-on

# เงื่อนไขสำคัญ
- แยกข้อมูลทั้งหมดไว้ไฟล์ data.js เพื่อเพิ่มความรู้ใหม่ได้โดยไม่แตะโค้ด
- ตัวเลขจากเอกสารให้ติดป้าย "จากเอกสาร" / ตัวเลขที่ยังไม่ยืนยันติดป้าย "ตัวอย่าง"
- ช่องข้อมูลที่ผมยังไม่มี (เช่น ชื่อ สจ. ทั้ง 10) ให้เว้นเป็นช่องกรอก ห้ามแต่งชื่อเอง
- เขียน README วิธีใช้ + วิธีเพิ่มข้อมูล ให้คนไม่เขียนโค้ดทำตามได้
```

## 3. Prompt ย่อยที่ใช้บ่อย (ตอนแก้งาน)

- **เพิ่มความรู้ใหม่:** "นี่คือข้อมูล Pump Capacity ของสถานี X: [วางข้อมูล] ช่วยเพิ่มเข้า
  KM_DATA ใน data.js และแสดงเป็นคอลัมน์ใหม่ในตาราง สจ. โดยไม่กระทบส่วนอื่น"
- **แก้กราฟ:** "กราฟ PTC ช่วงเย็นควรพีคที่ 20:00 ประมาณ 7.3 บาร์ ช่วยปรับจุดข้อมูลให้ตรง"
- **เตรียมนำเสนอ:** "สรุปเนื้อหาแต่ละ section เป็นสคริปต์พูดนำเสนอ 5 นาที สำหรับผู้บริหารที่ไม่รู้เทคนิค"
- **ตรวจความถูกต้อง:** "เทียบตัวเลขใน data.js กับข้อมูลดิบที่ผมแนบ แจ้งทุกจุดที่ไม่ตรงกัน"

## 4. ข้อควรระวังเมื่อใช้ AI กับงานประปา

1. **ตัวเลขปฏิบัติการห้ามให้ AI เดา** — Flow/Pressure/รหัส RTU ต้องมาจากหน้างานหรือเอกสารจริงเท่านั้น
2. **ข้อมูลภายในบางอย่างอาจเป็นความลับ** — ตำแหน่งวาล์ว/โครงข่ายละเอียดควรถามหัวหน้าก่อนป้อนเข้า AI สาธารณะ
3. **ให้ AI ติดป้ายแหล่งที่มาเสมอ** (จากเอกสาร vs ตัวอย่าง) เพื่อไม่ให้ตัวเลขสาธิตหลุดไปใช้ปฏิบัติการจริง
4. **ตรวจงานทุกครั้ง** — เปิดหน้าเว็บดูจริง กดทุกปุ่ม เทียบตัวเลขกับต้นฉบับ ก่อนส่งหัวหน้า
